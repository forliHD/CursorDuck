# Project conventions — Cursor Duck

## Language

**English is the project's lead language.** Everything that belongs to the
repository is written in English:

- source code: comments, identifiers, commit messages
- documentation: `README.md`, release notes, issues, pull requests
- the English locale `_locales/en/` is the reference; `default_locale` is `en`

**German is a fully supported product language, not a project language.**
It stays in place wherever users see it:

- `_locales/de/` is kept at feature parity with `_locales/en/` — both files must
  always hold the same set of keys
- store listings and screenshots are shipped in both languages
- `PRIVACY.md` is bilingual in one document (English first, German below) so the
  URL registered with all three stores stays valid

When a new UI string is added, add it to **both** locale files in the same commit.

## Product

A browser extension (Chrome, Firefox, Edge) that draws a duck following the
mouse cursor. Everything is rendered procedurally onto a canvas — **no image
assets at all**. Sounds are small bundled **CC0 recordings** in `audio/`
(played via Web Audio; a synthesized fallback covers load failures). Every
audio file must be CC0/public domain and documented in `audio/SOURCES.md`.

## Code

- Plain ES5-style JavaScript, no build step, no dependencies, no frameworks.
- `src/models.js` is pure data (colors, proportions, accessories, effects),
  `src/render.js` draws, `src/engine.js` holds physics and the behaviour state
  machine, `src/effects.js` holds particles.
- Motion is time-interpolated (`approach()`), never frame-based.
- The duck lives in a canvas inside a Shadow DOM with `pointer-events: none`.

## Releases

1. bump `version` in `manifest.json`
2. `python3 tools/build.py` → `dist/cursor-duck-chrome-<v>.zip` (MV3, also used
   for Edge) and `dist/cursor-duck-firefox-<v>.zip` (MV2, derived automatically)
3. `npx addons-linter dist/cursor-duck-firefox-<v>.zip` must report 0/0/0
4. push a tag, then `gh release create v<version> --verify-tag` with both zips

Store screenshots are generated by `demo/shots.html` and are deliberately free of
version-specific numbers, so they survive future releases unchanged.
